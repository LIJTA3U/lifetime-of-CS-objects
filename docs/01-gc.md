# 01. GC — отчёт по КТ №40 (Вариант 2)

## Цель

Измерить давление на управляемую кучу .NET для трёх сценариев аллокации (плюс принудительная сборка Gen2) и сравнить поведение счётчиков поколений GC.

## Метод

- `GC.GetTotalAllocatedBytes(precise: true)` — кумулятивный счётчик всех аллокаций с момента запуска (не текущий размер кучи, как `GC.GetTotalMemory`).
- `GC.CollectionCount(gen)` — количество сборок указанного поколения.
- `GC.GetGCMemoryInfo().HeapSizeBytes` — текущий размер кучи.
- Показания снимаются **до и после** каждого сценария, прирост вычисляется как разница.
- Объём выводится в мегабайтах.
- `GC.KeepAlive` предотвращает удаление "мёртвых" выделений JIT-компилятором.
- Реализация использует `readonly record struct` для `GcSnapshot` и `GcDelta` (соответствует эталону из методички).

## Среда запуска

- .NET 9, конфигурация Release
- Команда: `dotnet run --project src/MemoryLifecycle/MemoryLifecycle.csproj -- gc-pressure`

## Результаты (один из типичных прогонов)

```
=== Измерение давления на кучу (Вариант 2) ===

Сценарий                           Время, мс  Gen0  Gen1  Gen2  Alloc, МБ  Heap Δ, МБ
--------------------------------------------------------------------------------------------
Много мелких объектов (byte[100])       7,06     1     0     0      12,97        9,77
Несколько крупных объектов (byte[100_000])      0,02     0     0     0       0,95        0,00
Долгоживущие объекты в статическом списке      5,42     1     1     0      10,02        9,95
Принудительная сборка Gen2 (blocking)      3,86     1     1     1       0,00       -8,05
```

## Выводы

1. **Мелкие объекты нагружают Gen0.** 100 000 массивов по 100 байт аллоцируются в Generation 0 и быстро триггерируют его сборку — счётчик Gen0 растёт с 0 до 1, Gen2 не изменяется. Аллокаций ~12,97 МБ.

2. **Крупные объекты попадают в LOH, но не вызывают немедленной сборки Gen2.** Массивы больше 85 000 байт размещаются на Large Object Heap (поколение 2). Аллокация в LOH не увеличивает счётчик Gen0 и не увеличивает счётчик Gen2 до первой фактической сборки поколения 2 — поэтому Gen2 остаётся 0.

3. **Долгоживущие объекты раздувают кучу со временем.** Массивы, удерживаемые в `static List<byte[]>`, переживают сборки Gen0/Gen1 и перемещаются в Gen2. Прирост Gen0 (+1) виден сразу, а рост Gen2 проявится после следующей сборки поколения 2.

4. **Принудительная сборка Gen2.** `GC.Collect(2, GCCollectionMode.Forced, blocking: true)` всегда увеличивает счётчик Gen2 на 1, демонстрируя, что счётчик растёт только при реальной сборке поколения 2.
